# WS-1 Report — Where Scan Wall-Time Actually Goes

## Bottom line

Wall-time in an Abhedi Red engine-v2 scan is dominated by the **DISPATCH phase (worker LLM execution)**, not ledger/sync overhead — **H1 is REFUTED** by five of six auditors and the live DB. Each worker grinds up to ~280 Runner turns (6 reprompts × 40 turns) because weak proxied models (bunny/OpenRouter) rarely trip the offensive-gate — the live `decisions.log` is 100% `max_turns_exceeded`. That grind is re-paid across waves as **coverage thrash**: on the live 7.5h scan 1704/2989 applicable cells sit in `testing` limbo, so `count_claimable` never drains and the loop runs to the wall. Ledger/sync is cheap and mostly concurrent (periodic-sync and the exploit floor overlap dispatch and are cancelled on return). The real terminators in prod are the deliberate **time-based soft-cap drain** and **model HTTP errors** (×1082), not quiescence — and the residual clock backstop is a **deployed 24h wall**, not the ~90-min wall in the code/docs.

## Hypothesis touchpoints

- **H1** (slow scans = ledger/sync overhead, not coverage time) → **REFUTED**: sync is cheap and mostly concurrent; wall-time is DISPATCH turn-grind + testing-limbo thrash. Corroborated by 5 auditors + live DB (1704 testing vs 964 resolved; `decisions.log` 100% `max_turns_exceeded`).
- **H1a** (a wall/cap hit loses in-flight findings via SIGKILL-before-flush) → **PARTIAL**: per-worker wall does NOT (asyncio timeout→partial, /work flushed); the time-cap/cancel path DOES have a real 120s-ceiling SIGKILL window cutting finalize (live-confirmed). Proven findings survive via per-wave flush + salvage.
- **H1b** (concurrency mis-scaled by a fail-open health read) → **CONFIRMED (latent)**: `target_health`→1.0 silent; over-drives, never observed firing.
- **H1c** (a fail-open read cuts scan WORK short outside the loop-stop path) → **PARTIAL**: `_batch_done` `cell_states={}`→"satisfied" can preempt a working worker under a partial-DB flap; never fired in prod.
- **H-dispatch-dominates** → **CONFIRMED**: only phase running worker LLM loops; ~280 turns/worker with growing transcript.
- **H-run_all-barrier** → **CONFIRMED**: `fleet._one` uses only `wait_for(wall)`; the stuck-watchdog exists only on the `run_pool` path.
- **H-thrash** → **CONFIRMED**: 1704/2989 applicable cells in `testing`; `_batch_done` treats tool_calls increment as progress.
- **H(claim/release mismatch)** → **REFUTED**: batch releases by cell_id, escalation by same id; 0 cells stranded under any `batch{N}-` id; B1 fixes in HEAD.
- **H(leased-limbo in prod)** → **CONFIRMED, different cause**: 1622 floor-held + 37 wave-residue, all reclaimable-now.
- **H(stranded cells permanently stuck)** → **REFUTED**: claim OR-clause re-admits expired leases; `reclaim_expired_leases` per wave; 1976 claimable-now.
- **H(quiescence fails open)** → **REFUTED**: all three loop-stop reads fail closed + logged; double-gated true-quiescence; 0 read-failure events in prod.
- **H(attempt cap too low)** → **REFUTED**: only 0.9% reached `attempted` via cap; deployed cap is 6.
- **H(#30 attempted counted terminal)** → **CONFIRMED** (with lump-into-done caveat).
- **H(report coverage reconciles with ledger _OPEN_STATES)** → **CONFIRMED** (label "attempt-capped" misleading).
- **H(fleet never drains grid → finalize sweeps tail)** → **CONFIRMED**: `na_reason` 99% unreached; per-scan attempted% scales with grid size.
- **H(model halts after a few turns)** → **REFUTED**: live scan 5576 tool_invocations over ~1.86h (~50/min); `agent_messages` is a persistence artifact.
- **H(scanner-cp restarted mid-scan)** → **REFUTED**: restart 19:03Z precedes scan start 20:08Z.
