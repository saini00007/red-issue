## How to read the ON/OFF markers

A capability is only useful if you know whether it *runs* in a real deployment. Two layers decide that: the Python default in `src/scanner/config.py`, and the pin in `docker-compose.yml` (the tracked, real-deploy column). `docker-compose.override.yml` is dev-only and gitignored — ignore it for "what ships."

- **[ON]** — active in a stock `docker-compose.yml` deploy (either intrinsic to the live engine, or a flag pinned/defaulting on).
- **[OFF]** — *built and tested*, but default-OFF and not pinned on in compose, so a stock deploy does **not** run it. Opt in per-flag.
- **[OFF·compose]** — code default is ON but `docker-compose.yml` pins it OFF, so it's off in prod despite the code default.

**The exhaustive per-flag truth table (code default vs. compose pin) lives in [`docs/context/FLAGS.md`](./FLAGS.md).** This doc names the flag for each capability but does not repeat the full table. If FLAGS.md is absent, `config.py` field comments + `APPLICATION_CONTEXT.md` §7 are the current fallback source.

**Bottom line for a stock deploy:** the deterministic core (engine-v2 orchestration, ledger, exploit floor, recon floor, OOB, browser client-side proof, API discovery, A1 verifier, chain synthesis, reporting) is **ON**. Almost every Phase 0–5 addition (the oracle-first moat, boss-planner, two-identity/GraphQL/channels/AI surfaces, executed-chains, second-order, resume) is **built but OFF** pending per-flag opt-in and benchmark validation. This is deliberate: each new capability ships default-OFF and byte-identical to legacy until it's proven on the benchmark harness.

## 1. What it is

Abhedi Red is a **multi-tenant, black-box (and gray-box/credentialed) web + API penetration-testing platform**. An operator submits a scope (targets, optional credentials, optional playbook); the platform spins up an ephemeral fleet of containers per scan, drives LLM pentest agents **plus deterministic non-LLM exploit/recon backstops** against the target, persists findings/coverage/evidence/chains to Postgres (schema-per-tenant), and produces a buyer-grade VAPT report.

**Topology** (`docker-compose.yml` + `scheduler/worker.py`): a persistent stack (`postgres`, `redis`, `pgbouncer`, `scanner-cp` control plane, `frontend`, `nginx`) plus **ephemeral per-scan containers** spawned via the Docker SDK — `scanner/agent` (the LLM agent, non-root, no docker.sock), `scanner/toolserver` (Kali-rolling, 40+ tools behind a token-authed `/exec` HTTP endpoint), `scanner/browser` (Playwright/Chromium sidecar), optional `scanner/zap` and `scanner/tor`. The agent reaches Kali tools only over HTTP; it has no docker.sock and no host-root equivalence. All containers share one `/work` volume subpath per scan — the real cross-process shared memory.

**The proof-first thesis: "find AND prove-by-exploitation."** The design principle is *LLM proposes, deterministic oracle disposes*. A finding is only "verified" when a deterministic oracle fired, an out-of-band callback landed, or a browser actually executed the payload — prose reasoning alone never confirms. The benchmark's `proof_completeness` metric (`benchmark/metrics.py:_has_proof`) encodes this exactly: `verified is True` OR non-empty evidence artifacts count; a prose `proof_of_concept` does not.

## 2. Orchestration — engine-v2 is the only live path

**[ON — `SCANNER_ENGINE_V2=true`, code default AND compose]** Engine-v2 (`src/scanner/agent_runtime/engine/`) is the **sole orchestrator that runs by default**. The two legacy paths — the "planner"/Alpha-Team coordinator (`agent_runtime/planner/`) and the single-agent "reprompt" loop (`entrypoint.py:run_scan`) — are **dead code in a default deploy**; `entrypoint.main()` short-circuits to `_run_engine_v2()` before either flag is read. Do not reason about live behavior from `entrypoint.py`, `hooks/*`, `planner/*`, or `pipeline/*` — start at `engine/run.py:run_engine()` and `engine/father.py`.

- **Father / Fleet / Governor** (`engine/father.py` ~1930 lines, `engine/fleet.py`, `engine/governor.py`): Father is the wave-loop orchestrator. It builds `WorkerSpec` prompt strings and hands them to `FleetManager`, which runs each worker through one of two pluggable backends — `runtimes/claude_sdk.py` (Anthropic models) or `runtimes/agents_runtime.py` (everything else, via an OpenAI-compatible driver). Loop shape: recon → auth-bootstrap → `while` wave loop (materialize surface → sync `/work` to DB → check completion/quiescence → claim worklist → dispatch wave → chain-floor → escalation) → smoke workers → done. **Governor's numeric caps (`max_workers`/`max_invocations`/`max_wall_s`) are opt-in and default-OFF**; the primary stop condition is progress-based (plateau or unresolved==0), with a `SCANNER_ENGINE_RUNAWAY_WALL_S` (21600s/6h in compose) hard backstop.
- **Batch dispatch [ON — `SCANNER_ENGINE_BATCH_DISPATCH`, compose `true`, code default `False`]:** real deploys run the endpoint-scoped batch-pool path (`_run_batch_pool`/`_batch_specs`), not the legacy `run_all` fan-out. Workers claim endpoint-scoped cell batches; a `run_pool` on-done hook (`_release_worker_cells`) work-steals by releasing a finished worker's still-open cells (`release_cells_by_ids`) back to the pool — the collaborative pull-queue that fixed the "600s thrash." `SCANNER_ENGINE_SEAT_MODELS` is compose-`true` (code default `False`), so worker seats are bound to models pre-scan (strong→exploit/injection/access/logic/verifier, cheap→recon/desk).
- **The ledger coverage work-queue [ON — intrinsic]** (`src/scanner/ledger/service.py`): turns "is this scan done?" into a DB predicate. One `LedgerCell` row per **(surface element × applicable vuln-class)**; `ledger/applicability.py:is_applicable()` decides which of the **62 vuln classes** (`agent_runtime/taxonomy.py`, verified count) even make sense for an element (web surfaces = `url`/`api_operation`/`graphql`/`websocket`/`webhook`/`form`; the 5 AI classes apply *only* on a detected `ai_endpoint`). **Claim/lease** is a raw-SQL `SELECT … FOR UPDATE SKIP LOCKED` → `UPDATE … RETURNING`, so two workers (and the exploit floor) can never receive the same cell; claim order is priority-weighted so injection/authz/RCE cells front-load. **Attempt cap** (`SCANNER_LEDGER_ATTEMPT_CAP=3`) retires a cell to terminal `attempted` rather than looping forever. **Completion:** `scan_is_complete()` = `open==0` OR resolved-ratio ≥ 0.98; `graceful_terminal_status()` returns `completed` only if resolved AND there was applicable coverage, else `partial`.
- **Deterministic floors run *beside* the LLM, every wave [ON]:** the exploit floor and recon floor (see §4) claim *disjoint* cell batches from the same ledger via the same SKIP-LOCKED mechanism, guaranteeing a coverage floor independent of what the LLM chooses to do.
- **Boss-as-planner [OFF — `SCANNER_ENGINE_BOSS` (+ `SCANNER_ENGINE_PLAYBOOK`)]:** `engine/boss.py` + `plan.py` + `plan_gate.py` + `policy.py` are built — a bounded boss tick emits `plan.json` that biases Father's wave loop, and the operator playbook becomes a scan-brief PLAN/PHASES directive. Default-OFF ⇒ Father runs its deterministic wave loop with no planner bias, exactly as today.

## 3. Proof primitives

The disposal side of "propose/dispose." All route through the same `/work` JSONL → ledger ingest path, so a proof from any source lands as a verified finding with no bespoke plumbing.

- **Response-diff / in-band oracles [ON]** (`engine/exploit_floor.py`, `agent_runtime/oracle_map.py`): deterministic verdicts over tool/HTTP output — sqlmap confirmation, dalfox reflection, nuclei matches, differential probes. `oracle_map.required_oracle_for` maps each class through its phase-group to a class-appropriate oracle tool: injection→`sqlmap`, access→`jwt_tool`, clientside→`dalfox`, config catch-all→`nuclei`, logic→`curl`.
- **OOB (out-of-band) callback correlation [ON — `SCANNER_OOB_AUTOLINK=true`]** (`agent_runtime/oob/`, `interactsh.py`): deterministic, zero-LLM-trust join of a self-hosted-oracle callback back to the payload that caused it. **Honest classification is the core anti-false-positive mechanism** (`oob/service.py`): the callback's *wire protocol* decides the class, not the agent's self-label — `ldap`/`ldaps`/`rmi` → `jndi` (Log4Shell), anything else proves only "server reached attacker infra" = SSRF-class, and any other claimed label (sqli/cmdi/rce) on such a beacon is **downgraded to `ssrf`** with a suspicion note. This killed the historical mass "confirmed via OOB" false-positive bug. Findings capped at `SCANNER_OOB_MAX_FINDINGS` per scan. **Caveat:** `scanner_oob_server` code default and compose default are both `https://oast.fun`; a real engagement is expected to override `SCANNER_OOB_SERVER`/`SCANNER_OOB_TOKEN` to the self-hosted oracle — **verify the live env, don't trust the default.**
- **Browser client-side execution proof [ON — `SCANNER_BROWSER_ENABLED` + `SCANNER_BROWSER_INSTRUMENT_ENABLED`, both compose `true`]** (`docker/browser/`, `agent_runtime/browser_ingest.py`): the sidecar's `/instrument` route proves **three classes by real Chromium execution**, all routed by the `_INSTRUMENT_KIND_MAP` `kind`→(class,severity,verb) table (`instrument_hit_to_finding`) into the normal `findings.jsonl`→ledger path with zero new ingest code — **DOM-XSS** (`dom_xss`→`xss_dom`, a canary-tainted sink actually fires, `executed:true`), **prototype-pollution** (`prototype_pollution`, plant `__proto__[prop]=canary` via URL query-merge then read `({})[prop]===canary` live), and **web-storage secret leak** (`storage_leak`→`secrets_exposure`, live `localStorage`/`sessionStorage` matched against secret regexes, value masked). **Only `executed==True` hits mint findings** — a bare taint/string match is dropped. Also active in `thorough` mode even if the instrument flag were off (`config.browser_instrument_on`). Deferred client-side classes (CORS live round-trip, CSP-external-script, service-worker enum) are documented SKIPs with extension points.
- **Browser HAR offline proof [ON — rides `SCANNER_BROWSER_ENABLED`]** (`browser_ingest.py:sync_har_proof`/`_har_proof_row`): for the four offline-computable API access classes (`idor_bola`/`bfla`/`auth_bypass`/`mass_assignment`), the recorded Playwright HAR is sliced by (endpoint, method, vuln_class) into the exact authed request/response **pair** and attached as a finding-scoped `EvidenceObject` (never the multi-hundred-MB blob) — the pair *is* the proof (BOLA returns another user's object, mass-assignment reflects the extra field). Recon screenshots/HAR also persist as scan-level `EvidenceObject(kind="recon")` via `sync_browser` (a gallery reference, never attached as finding proof). Live-capture DOM/stored-XSS pop-shots + low-priv admin-response renders are a documented deferred seam.
- **Deterministic exploit-floor oracles [ON — `SCANNER_EXPLOIT_FLOOR_ENABLED=true`, config default `True` + compose `true`]:** only *unambiguous* oracles mint a `verified=True` finding directly; ambiguous hits go to `exploit_floor_signals.jsonl` for LLM triage. **Known gap:** the `hygiene` family (`exploit_floor.py:_HYGIENE`) claims `WEAK_CIPHER` and `CERT` cells but its actual probes are only header-dump, plain-HTTP/TLS-*enforcement* downgrade (`build_http_downgrade_cmd`), and verbose-error signatures — there is **no cipher-suite-strength (`WEAK_CIPHER`) or certificate-validity (`CERT`) oracle** (no sslscan/testssl). Those two classes ride the hygiene claim and read "probed" without a real cipher/cert check, so the coverage board over-counts them. (Similarly, `file_upload` cells are opened by applicability but only swept when `SCANNER_UPLOAD_SWEEP=1`, default OFF — no active upload probe in a stock deploy.)
- **Unified proof-capsule [OFF — `SCANNER_REQUIRE_PROOF_CAPSULE`]** (`agent_runtime/evidence.py`, `finalize.py:backfill_proof_capsules`): when on, a canonical proof capsule is a **structurally-required field on every confirmed high/critical**; finalize backfills it onto oracle/OOB/HAR-proven findings, and the report gate routes any verified H/C carrying no capsule to "Unconfirmed / needs manual review." Default-OFF ⇒ report output byte-identical.
- **Oracle-first confirm + pending states [OFF — `SCANNER_ORACLE_FIRST`]:** when on, a finding reaches `confirmed` only on machine proof (linked evidence or a fired class oracle); a prose/model-verdict-only claim is routed to a `pending_oracle`/`pending_human` cell state, and a verifier that *couldn't run* flips to `pending_human` instead of failing open. This is the keystone of the "moat"; default-OFF ⇒ byte-identical legacy confirm.
- **Detached verify [OFF — `SCANNER_DETACHED_VERIFY`]** (`engine/detached_verify.py`): re-fires each H/C finding's captured proof request deterministically (httpx, no toolserver, no LLM) on toolserver-less finalize paths (poller salvage / cancel / dead-node), which today skip reproduction.
- **Honesty close-gates [OFF — all]:** `SCANNER_EVIDENCE_GATE`, `SCANNER_LEDGER_MACHINE_CLOSE`, `SCANNER_LEDGER_SKILL_GATE` each tighten when a ledger cell may close (proof artifact present / a real tool hit the endpoint / the class-appropriate oracle fired). All default-OFF and compose-OFF ⇒ legacy close semantics in prod.

## 4. Surfaces & coverage

Coverage is defined by the ledger: **62 vuln classes** (`taxonomy.py`) × discovered surface elements. Framework refs (CWE/OWASP/ATT&CK/D3FEND) are attached per class.

**Recon floor [ON — deterministic, `SCANNER_RECON_DEPTH=1`]** (`engine/recon_floor.py`, `context.py`, `attack_surface.py`): subfinder→httpx(+arjun)→katana feeding the same inventory sniffer the rest of the pipeline uses, plus 5 gated depth stages. Auth bootstrap (`auth_bootstrap.py`) logs in deterministically (httpx) first, LLM self-register fallback second.

Classic web classes covered by the **exploit floor + LLM fleet [ON]**: injection (sqli/nosqli/ssti/cmdi/ldap/xpath/xxe/ssi/crlf), reflected/stored/DOM XSS, access (idor_bola/bfla/priv_esc/auth_bypass/forced_browse), ssrf/lfi/rfi/open_redirect/deserialization/file_upload/prototype_pollution, http (smuggling/cache_poisoning/host_header), auth (default_creds/weak_session/jwt/oauth_saml), info-exposure (secrets/sourcemap/backup/vcs/debug/dir_listing), infra (open_service/takeover/cloud_bucket/missing_email_auth), crypto (weak_cipher/cert/protocol — see the exploit-floor gap in §3), logic (workflow_abuse/price_tamper/race_condition/mass_assignment/quota_abuse), client-side (csrf/cors/security_headers), and API-specific (graphql/excessive_data/rate_limit). How each is proven follows the §3 primitives — sqlmap/dalfox/nuclei oracles, OOB for blind classes, browser execution for DOM-side.

**Exploit-floor family structure** (`exploit_floor.py:_FAMILIES`, disjoint class sets): eight always-on families, each bound to a primary weapon — `injection`→`sqlmap` (sqli/nosqli), `config`→`nuclei` (cors/default_creds/dir_listing/backup/vcs/sourcemap/secrets/debug/host_header/cache_poisoning/open_service/takeover/cloud_bucket — the misc catch-all), `hygiene`→`curl` (security_headers/weak_session/protocol + the claimed-not-probed weak_cipher/cert), `clientside`→`dalfox` (reflected/stored/DOM XSS), `blind`→`oob` (ssrf/ssti/cmdi/xxe/lfi/rfi/open_redirect/deserialization — the OOB-provable set; `_SSRF` was renamed "blind" for honesty), `access`→`curl` differential (anon-200 on a protected endpoint self-proves; every other diff is an LLM-triage signal), `logic`→`curl` (candidate-signal only, never self-proving), and `ratelimit`→`curl`. A `nofamily` curl sweep (default-on, `SCANNER_NOFAMILY_SWEEP`) drains *first* over the cheap hardening classes (security_headers/cors/host_header/csrf/excessive_data/cache_poisoning) with precise active probes. Three more families are **flag-gated OFF**: `authclass` (crlf/smuggling/oauth_saml/jwt_flaws, `SCANNER_AUTH_ORACLES_ENABLED`), `upload` (`SCANNER_UPLOAD_SWEEP`), and `ai` (`SCANNER_AI_REDTEAM_FLOOR` + `ai_endpoint` detection).

**API discovery [ON — `SCANNER_API_DISCOVERY_ENABLED=true`, `config.py:345` default `True` + compose `true`]** (`agent_runtime/inventory_ingest.py`): parses the `api_discovery` log (OpenAPI spec-hunt / kiterunner / GraphQL introspection + the browser's XHR/form body-param records) into templated `api_operation` inventory elements, which the ledger opens API cells over. **Shadow/zombie/debug operations** surface as `exposure.shadow_api` findings off this flag (producer self-gates to byte-identical when there's no API surface). Operator-supplied HAR/Postman import is gated `SCANNER_API_IMPORT` **[OFF]** and the data-var wiring (`SCAN_API_IMPORT`) is a known benchmark-track follow-up.

The following surfaces are **built but flag-gated OFF** — each self-gates on detection, so even when flipped on it's byte-identical against a target lacking that surface:

- **GraphQL authz + BOPLA [OFF — `SCANNER_GRAPHQL_AUTHZ_ENABLED`]** (`engine/graphql_authz.py`): schema-driven post-drain pass — per-field/per-mutation two-identity authz (create-as-A / query-as-B, direct AND nested), a BOPLA property-diff, and a depth/batching-abuse oracle; each fires on a deterministic verdict over parsed GraphQL JSON.
- **WebSocket / SSE / webhook channels + sequence replay [OFF — `SCANNER_CHANNEL_ORACLES_ENABLED`]** (`engine/channels.py`): websocket+webhook cells (cross-user message leak / unauth channel-open / webhook signature-bypass) plus operator-recorded multi-step flow replay from `/work/sequences.json`.
- **SSO/OAuth login + authed-SPA crawl [OFF]** (`SCANNER_SSO_LOGIN`, `SCANNER_BROWSER_AUTHED_CRAWL`, `SCANNER_BROWSER_REAUTH`): federated (OAuth/OIDC/SAML) login primitive, planting a captured session into SPA storage so the crawl boots logged-in, and mid-crawl session-death detection + re-plant. Base credentialed/gray-box login (deterministic httpx + LLM fallback) is **[ON]** in the recon path; these are the *browser-depth* extensions.
- **Multi-tenant isolation:** two-account authz **[OFF — `SCANNER_TWO_IDENTITY_AUTHZ_ENABLED`]** (planted-canary create-as-A/read-as-B BOLA/BFLA) and cross-tenant isolation **[OFF — `SCANNER_CROSS_TENANT_ENABLED`]** (replay each object endpoint as `tenant_b`, plant a `tenant_a` canary, prove cross-read). Both detection-gated on `auth.json` carrying the second identity. Note this is *target* multi-tenancy testing; the *platform's* own tenant isolation (schema-per-tenant, §6) is always-on and separate.
- **AI/LLM/MCP endpoints [OFF — `SCANNER_AI_REDTEAM_FLOOR`, double-gated]** (`engine/ai_redteam.py`, `recon_floor.py:_stage_ai_detect`): 5 AI classes (prompt-injection, indirect-injection, system-prompt-leak, tool-abuse, RAG-leak; OWASP LLM Top-10 / MITRE ATLAS). **Double-gated:** the flag AND a runtime detection witness (an `ai_endpoint` element only exists when recon proves an OpenAI-compatible/MCP surface) — no AI surface ⇒ zero AI cells ⇒ byte-identical. Each probe fires on an in-band oracle (verbatim canary echo, recorded tool-call, or OOB sink).

## 5. Chaining & second-order

- **Chain synthesis in the report [ON — `SCANNER_CHAIN_SYNTHESIS=true`]** (`agent_runtime/chain/service.py`, `capabilities.py`): builds the finding-chain graph and synthesizes ranked attack chains from confirmed capabilities (a confirmed finding grants a `Capability` like `FILE_READ`/`CREDENTIAL`; the capability tables say which classes it unlocks). Shared live code across engine-v2, finalize, and reporting.
- **Deterministic chain-floor next-hop prober [OFF·config — `SCANNER_ENGINE_CHAIN_FLOOR=0` in compose]** (`chain/floor.py:run_chain_floor`): fires a deterministic single-hop follow-up from a granted capability (e.g. metadata-access→IMDS credential theft). Engine-v2-only. Compose default `0` ⇒ off; raise the count to enable.
- **Executed-chain findings [OFF — `SCANNER_EXECUTED_CHAIN_FINDINGS`]** (`chain/floor.py:_write_executed_chain`): composes one `executed_chain` finding from an already-CONFIRMED source primitive **plus** the follow-on hop this floor just PROVED (both rows independently verified — never a prose-only confirm), routed to the report's "Executed (proven end-to-end)" bucket. Default-OFF ⇒ that bucket stays empty.
- **SSRF impact classification + cloud exfil [OFF — `SCANNER_SSRF_CLOUD_EXFIL`]** (`chain/floor.py`): injects bucket LIST/read URLs *through* the in-scope SSRF param (never a direct storage-host connection) and confirms on a deterministic listing body → distinct CRITICAL `cloud_bucket` exfil finding. (Base SSRF classification via OOB honest-classification is **[ON]**, §3.)
- **Deferred / second-order confirmation [OFF — `SCANNER_DEFERRED_CONFIRMATION`]** (`exploit_floor.py` + `oob/service.py:sync_deferred`): a stored/second-order canary that didn't confirm immediately is registered in `deferred_registry.jsonl`; a later file-based reconcile re-scans captured artifacts for that canary echoed un-encoded and mints a verified finding. Poller-safe (reads files, fires no request).
- **Session-class checks [OFF — `SCANNER_AUTH_ORACLES_ENABLED`]** (`exploit_floor.py` authclass family): deterministic oracles for the hard auth classes — JWT `alg:none`/kid, OAuth `redirect_uri`/PKCE, session fixation/rotation/revoked-token-replay, CRLF header-split, and a safe timing-differential request-smuggling probe. Also gates the P4-C session no-rotation check.
- **Template reachability labels [OFF — `SCANNER_TEMPLATE_REACHABILITY_LABELS`]** (`exploit_floor.py`): version-only nuclei/tech-fingerprint matches (CVE-by-version inference) are relabeled `reachable`/`needs_confirmation` (`verified=false`, no proof capsule, routed to the report's Unconfirmed section) instead of shipping as verified "proof." **Version-only ≠ proof** — but default-OFF today means a version match still ships verified in a stock deploy.

## 6. Reliability

- **Multi-tenant platform isolation [ON — intrinsic]:** schema-per-tenant in Postgres, enforced by `SET search_path`, not by ORM `tenant_id` filters. Gray-box target credentials encrypted at rest (`config.encrypt_credentials`, HMAC-SHA256 encrypt-then-MAC; `MASTER_ENCRYPTION_KEY` empty ⇒ passthrough plaintext — set it in prod).
- **Idempotent salvage funnel [ON]** (`scheduler/poller.py:_finalize`): every exit path (clean success, crash-with-report, crash-with-checkpoint, crash-with-partial-artifacts, cancel, close, GC dead-node recovery) routes through one salvage funnel. GC dead-node recovery specifically un-sticks scans whose owning node died in `killing`/`cancelling`/`closing` (a prior 2-day-stuck incident). **Caveat:** a salvaged scan gets a *weaker* verification pass than a clean exit — the poller has no toolserver token, so reproduction-verify self-skips (this is what `SCANNER_DETACHED_VERIFY`, §3, addresses).
- **Ledger-resume on scanner-cp crash + operator resume endpoint [OFF — `SCANNER_ENGINE_RESUME`]:** when on, a crashed/restarted engine-v2 scan is **re-spawned against its persisted ledger + `/work` (continuing from OPEN cells)** instead of being salvage-finalized, and `POST /scans/{id}/resume` is enabled (detects `/work/resume.json`). CP-process-only. Default-OFF ⇒ the poller branch is skipped and the endpoint 409s — **the "never restart scanner-cp mid-scan" hazard is still live until this flag is flipped on.**
- **Graceful termination [ON]:** SIGTERM handling distinguishes a graceful time-cap drain (freeze new work, drain in-flight, finalize) from an operator close. `graceful_terminal_status()` is the single coverage-gated rule for `completed` vs `partial`.
- **Honest coverage counts [ON]:** `scanner_finalize_retire_unreached` (default ON) retires never-genuinely-probed applicable cells to terminal `attempted` so `count_open_cells` can reach 0 and a genuinely-ended scan reads `completed` — and `attempted` is **not** counted as resolved, so the coverage % stays honest. (Known nuance: two code paths disagree on whether `attempted` cells are "resolved" vs "neither" — see CLAUDE.md Known Issues; report math §7.)

## 7. Reporting & evidence

- **Persistence [ON]:** findings, coverage (ledger cells), chains, and evidence objects all persist to the tenant DB. Raw tool outputs live on the `/work` filesystem; structured data in Postgres. `WorkerRecorder` (`engine/telemetry.py`) is the sole writer of `scan_phases`/`worker_runs`/`agent_messages`/`scan_events` and the sole publisher to the live WebSocket feed. **Caveat:** cost/token telemetry comes only from `agents_runtime.py` (non-Anthropic); Anthropic-model workers via `claude_sdk.py` contribute zero cost telemetry.
- **Report assembly [ON]** (`reporting/service.py:build_report`): recomputes CVSS live (a valid vector wins over stored severity), drops soft-dedup losers, stamps OWASP/ATT&CK/D3FEND refs, attaches deterministic remediation for 5 safe classes, joins OOB proofs, gates headline-vs-unconfirmed via `exploit_quality.is_unconfirmed()`, rolls up a severity-weighted risk score, synthesizes ranked chains. Rich grounded VAPT report is **[ON — `scanner_report_v2` code default True, not overridden]**; degrades to the deterministic pack absent a verifier model.
- **A1 verifier pass [ON — when a non-Anthropic verifier model exists]** (`agent_runtime/finalize.py:finalize_scan`): an independent post-scan pass re-reproduces self-declared critical/high findings and downgrades unconfirmed ones. **An all-Anthropic roster gets no A1 verifier and no close-sweep** — the verifier endpoint excludes Anthropic providers (they can't drive the OpenAI-compatible verifier SDK path).
- **Report coverage math [ON — but a known inconsistency]:** the report excludes `attempted`-state cells from both `resolved` and `open`, so an "X/Y resolved; N open" line can have `X+N < Y`, while the ledger's own `_OPEN_STATES` treats `attempted` as effectively resolved. Two code paths disagree on the same state (tracked in CLAUDE.md Known Issues).
- **Cross-scan regression diff [ON]** (`reporting/regression.py`): stateless cross-scan diff, reachable at `GET /scans/{id}/diff`. **Two HTML renderers diverge:** finalize writes a rich tiles/bars/SVG report to disk; the live `GET /report?format=html` API serves a plainer version (and `report.effort` is always empty over the API).

## 8. Benchmark harness — the measurement instrument

`benchmark/` (repo root, `python -m benchmark.run`) is how capability changes are proven or regression-caught. It brings each containerized target up via its own `compose.yaml`, submits a scan through the real API, polls to terminal status, scores, and tears down. An unreachable target is recorded and skipped, not fatal.

- **FLAG scorer [built]** (`metrics.py:extract_flags`/`flag_solved`, `run.py:_score_flag`): scrapes every string field of every finding for `FLAG{…}` and **sha256-matches against a committed hash** (so the plaintext flag never lives in the repo). This is how XBEN/XBOW-style capture-the-flag challenges are scored.
- **Proof-completeness metric [built]** (`metrics.py:proof_completeness`): fraction of findings carrying a fired oracle / hard evidence (`verified is True` OR non-empty `evidence_paths`). **Prose `proof_of_concept` deliberately does not count** — this metric *is* the proof-first thesis, quantified. Emits `findings_total`, `findings_proven`, `proof_completeness`, and an `unproven` triage list.
- **Recall / false-positive scorer [built]** (`metrics.py:compute_metrics`): scores canonical `"<vuln_class>:<endpoint>"` keys against a target's `ground_truth.yaml` — `recall`, `false_positives`, `missed`, `missed_by_class`.
- **Baseline / regression comparator [built]** (`regression.py:compare_to_baseline`, `run.py --check-regressions`): compares recall (5% tolerance) and `flag_solved` against `benchmark/baseline.json`, exits 1 on any regression. New targets don't gate; improvements never regress.
- **Targets [present]** (`benchmark/targets/`): `vampi` (VAmPI — Flask + OpenAPI API target, BM-6), plus `crapi`, `juice-shop`, `webgoat`, `dvwa`, `portswigger`, `metasploitable`, `vulhub-subset`. Plus the **XBEN/XBOW-104 adapter [built]** (`xben.py`, `run.py --xben-root`) that discovers a checked-out `xbow-engineering/validation-benchmarks` tree as flag-scored targets without vendoring 104 dirs.
- **Scope-mode network wiring [built, opt-in]** (`netwire.py`, `run.py --netwire`): attaches a compose-launched target to its scan's per-scan Docker bridge network (found by the `scan_id=<id>` label) with the scope hostname as an alias, so a target that binds no host port is still reachable from inside the scan. Best-effort; a docker hiccup returns False, never raises.

**Uncertain:** `run.py:_load_ledger_summary` documents that **no API/admin route currently exposes ledger coverage counts** to the benchmark, so per-target `coverage` is a forward-compatible hook (reads an optional `ledger_summary.json`), not a wired pipeline. Coverage-in-benchmark is not fully closed-loop today.

## 9. Model-agnostic driver

**[ON — intrinsic, zero extra code]** The driver is model-agnostic via **per-entry `api_base`** on each roster/model entry (`engine/registry.py:13` `api_base: str | None`, read at `:32`). Any OpenAI-compatible endpoint — self-hosted vLLM, or a LiteLLM/OpenRouter proxy fronting Anthropic/DeepSeek/GLM/GPT/etc. — is reached by pointing `api_base` at it; the proxy handles per-provider auth and translation. Anthropic models run through `runtimes/claude_sdk.py`; everything else through `runtimes/agents_runtime.py` (the OpenAI-Agents-SDK-compatible path). For Anthropic specifically, `ANTHROPIC_BASE_URL` can also redirect the Claude Agent SDK at an Anthropic-format proxy. Live multi-model runs (GLM + GPT + DeepSeek through a proxy) confirm it; **no dedicated per-provider SDK or key-vault exists and none is planned** unless a real need for 2+ direct remote-provider keys with no proxy appears.

## 10. Known gaps & honest caveats (code-verified)

The platform is deliberately conservative about what it calls "proven." These are the real gaps in a **stock deploy** — each was re-read against the file before listing. See CLAUDE.md "Known Issues (Code-Level)" and `docs/APPLICATION_CONTEXT.md` §6 for the deeper bug list; this is the capability-facing subset.

- **`WEAK_CIPHER` / `CERT` claimed-but-not-probed** (`exploit_floor.py:_HYGIENE`): no cipher-suite or certificate-validity oracle exists (only a TLS-*enforcement*/plain-HTTP downgrade check). Those cells read "probed" without a real check → coverage over-count. **`file_upload`** likewise has no active floor probe unless `SCANNER_UPLOAD_SWEEP=1` (default OFF).
- **No semantic memory in the running system** — `engine/context_memory.py:MemoryStore` (pgvector-backed recall) has **zero callers anywhere in `src/`** outside its own test. Dead code; don't assume any cross-turn semantic recall exists.
- **Version-only matches still ship verified in stock** — the `SCANNER_TEMPLATE_REACHABILITY_LABELS` relabel is default-OFF (§5), so a nuclei tech/CVE-by-version fingerprint currently ships as a verified finding rather than "needs confirmation."
- **Salvage-path verification is weaker** — poller salvage / cancel / dead-node finalize has no toolserver token, so the A1 reproduction pass self-skips (§6). `SCANNER_DETACHED_VERIFY` (default OFF) is the fix.
- **All-Anthropic roster gets no A1 verifier and no close-sweep** — the verifier endpoint excludes Anthropic providers (`engine/run.py:_verifier_endpoint`, needs a non-anthropic model with an `api_base`); it also carries all cost/token telemetry, so an all-Anthropic run reports ~zero cost (§7).
- **`scanner_inventory_ingest_v2` config-default-ON but compose pins it OFF** — the engine's live ingest forces `enable_v2=True` regardless (`attack_surface.materialize`, §4), so the coverage grid is unaffected, but the legacy finalize/reprompt inventory producer runs the pre-v2 path in prod.
- **OOB defaults to the public `oast.fun`** — both `config.py` and compose default `SCANNER_OOB_SERVER=https://oast.fun` (§3). A real engagement must point it (and `SCANNER_OOB_TOKEN`) at the self-hosted oracle; **verify the live env, don't trust the default.**
- **Report coverage math vs. the ledger disagree on `attempted` cells** — the report excludes `attempted` from both resolved and open, while the ledger's `_OPEN_STATES` treats it as resolved; an "X/Y resolved; N open" line can have `X+N < Y` (§7).
- **`MASTER_ENCRYPTION_KEY` empty ⇒ gray-box creds stored plaintext**, silently (`config.encrypt_secret` passthrough); compose declares it optional `${VAR:-}`, unlike the fail-closed `${VAR:?}` DB/Redis passwords (§6).
- **Benchmark coverage is not closed-loop** — no API/admin route exposes ledger counts; per-target `coverage` is a forward-compatible hook reading an optional `ledger_summary.json` (§8). Operator HAR/Postman `SCANNER_API_IMPORT` is OFF and its `SCAN_API_IMPORT` data-var wiring is a benchmark-track follow-up (§4).
